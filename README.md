# StudyBudget：留學生記帳

給留學生用的記帳 App。台幣帳戶和當地貨幣一起記，總額自動換算；在國外刷台灣的信用卡，也會幫你估算含海外手續費的台幣扣款。

**👉 立即使用：<https://bookkeeping-app-three.vercel.app/>**

- **不用註冊**：打開網頁就能用，可以加到手機主畫面當 App。
- **離線可用**：沒有網路也能記帳，只有下載匯率時需要連網。
- **資料只在你的手機上**：記帳資料存在瀏覽器裡，不會上傳到任何伺服器，所以**記得備份**（按一下就好，見下方）。

## 開始使用

### 1. 打開 App，加到主畫面

用手機瀏覽器打開 <https://bookkeeping-app-three.vercel.app/>，然後加到主畫面（想自己架一份，見下方「部署」）：

- **iPhone**：用 Safari 打開，點下方的「分享」→「加入主畫面」。
- **Android**：用 Chrome 打開，點右上角選單 →「安裝應用程式」。

加到主畫面後就像一般 App 一樣從桌面打開，沒網路也能用，瀏覽器也比較不會清掉資料。iPhone 只在 Safari 分頁裡使用的話，Safari 可能會清除太久沒開的網站資料，所以建議一定要加到主畫面。

### 2. 第一次設定（約 1 分鐘）

第一次打開會有三個步驟：

1. **你在哪裡讀書**：選當地幣別（例如日圓）和家鄉幣別（例如台幣），以及總額要換算成哪一個。
2. **你有哪些帳戶**：勾選會用到的帳戶，例如現金、當地銀行、台灣的銀行和信用卡；餘額可以先空著，之後再改。台灣的信用卡會預填 1.5% 海外交易手續費。
3. **資料存在你的手機裡**：說明備份和加到主畫面。

換手機的人，在第一個畫面選「從備份檔還原」就好。

## 每天記帳

點底部中間的 **「+」**（任何頁面都有）：

1. **輸入金額**：金額就在最上面。
2. **點分類**：例如外食、交通。
3. **按「儲存」**。

帳戶會先選好你最近最常用的；要換的話，點金額下面那一排帳戶。其他捷徑：

- **常用**：常去的店會出現在這裡，點一下就只剩金額要填。
- **今天／昨天**：補記昨天的帳，點日期旁的「昨天」。
- **商家**：輸入以前用過的商家時，會自動帶入上次的分類。
- **再記一筆**：要連續記好幾筆時用，存完表單不會關掉。
- **存錯、刪錯**：畫面下方會短暫出現「復原」，點一下就回到原本的樣子。

## 常見情況怎麼記

| 情況 | 怎麼記 |
| --- | --- |
| 在國外刷台灣的信用卡 | 點金額左邊的幣別，改成當地幣別（例如 JPY），輸入刷卡金額。App 會依匯率和卡片手續費估算台幣扣款，列表上標「估」。帳單出來後，到「帳戶」點那張卡的「N 筆估計的扣款待核對」，逐筆改成實際金額，或勾「已和帳單核對」。 |
| 朋友還你代墊的錢、退貨退款 | 類型選「退款」，分類選原本那筆的分類（例如外食）。會從那個分類的支出扣掉，不會算成收入。 |
| 家裡匯錢過來、提款、繳卡費 | 類型選「轉帳」，選轉出和轉入的帳戶。轉帳不算收入也不算支出；跨幣別時兩邊金額分開填，有手續費也可以一起填。 |
| 房租、訂閱、每月生活費 | 記帳時打開「更多：備註、每月固定」，勾選「每月固定」。之後每個月到期時，交易頁會提醒你，按「記上」才會記錄，也可以按「略過」。到「設定 → 固定收支」可以改金額或停止。 |
| App 的餘額和銀行對不上 | 到「帳戶」點那個帳戶，直接把「目前餘額」改成銀行 App 上的數字。 |
| 找以前的某筆紀錄 | 交易頁點放大鏡，搜尋商家、備註或分類名稱，會找遍所有月份。 |

App 右上角的 **「?」** 有更完整的使用說明。

## 看花了多少

「概況」會把所有幣別換算成主要幣別。最上面可以切換：

- **月**：本月支出、收入、結餘，錢花在哪些分類（點分類可以看明細），以及帳戶合計。設定每月預算後，會顯示還剩多少、每天平均可以花多少；預算可以用任何幣別，例如 ¥80,000。
- **學期**：整個學期的總支出、每月平均、每個月花了多少（點一下進到那個月），以及各分類逐月的變化。上學期從幾月開始可以在頁面最下面調整；沒調整前依手機時區預設：日本 4 月、澳洲和紐西蘭 2 月、其他地區 9 月。
- **年**：一整年（1 到 12 月），內容和學期相同。

匯率每天自動更新（來源：[currency-api](https://github.com/fawazahmed0/exchange-api)，有台幣），會存在手機上，所以離線也能換算。還沒有匯率的幣別會另外標出來，不會被當成主要幣別硬加進總額。

## 備份與換手機

因為資料只存在這支手機上，手機遺失、換手機，或清除瀏覽器資料時，資料都會不見。**請定期備份。**

- **一鍵備份**：超過 7 天沒備份時，交易頁上方會出現提醒。按 **「立即備份」** 會打開分享選單，選「儲存到檔案 → iCloud 雲碟」、Google 雲端硬碟，或傳給自己的 LINE 都可以。電腦上則是直接下載檔案。
- **隨時備份**：「設定 → 資料備份」可以下載或分享備份檔（`studybudget-日期.json`）。
- **換手機、還原**：在新手機打開 App，第一個畫面選「從備份檔還原」；或到「設定 → 從備份還原」選備份檔。還原前會先顯示檔案內容讓你確認，還原後如果發現選錯檔案，也可以立即復原。
- **減少被清除的機會**：「設定 → 儲存空間」可以要求瀏覽器永久儲存（加到主畫面後通常就能啟用）。
- **用試算表分析**：「設定」可以匯出 CSV，用 Excel、Numbers 或 Google 試算表打開。CSV 不能用來還原，備份請用上面的備份檔。

## 常見問題

**資料會上傳嗎？**
不會。記帳資料只存在這支手機的瀏覽器裡；App 只會連網下載匯率，不會送出你的任何資料。備份檔也只會存到你自己選的地方。

**沒有網路能用嗎？**
可以。記帳、看概況、備份都不需要網路，只有更新匯率時需要。

**可以在手機和電腦同時用嗎？**
不能同步。兩台裝置的資料是分開的；要搬資料，可以在一台備份、另一台還原（還原會取代那台原本的資料）。

**可以改語言或深色模式嗎？**
可以，在「設定」：繁體中文／English，淺色／深色／跟隨系統。

## 功能一覽

- **交易**：支出、收入、退款、轉帳；依月份瀏覽，依帳戶、類型、分類篩選；搜尋會找遍所有月份並加總結果。
- **多幣別**：每個帳戶有自己的幣別；跨幣別轉帳兩邊金額分開記，並顯示換算出的匯率；轉帳手續費會另記一筆支出。
- **外幣刷卡**：輸入原幣金額，依匯率和卡片海外手續費估算扣款；手續費在概況中歸到「手續費」分類；帳戶頁會列出待核對的估計扣款。
- **帳戶**：餘額一律由交易推算，可以直接改成目前餘額來校正；有交易的帳戶可以封存，但不能刪除或改幣別；現金或電子錢包變成負數時會提示。
- **分類**：可以新增、改名、換圖示，或隱藏用不到的。
- **固定收支**：每月到期時提醒，確認後才記錄；錯過的月份會依序補上。
- **報表**：月、學期、年；每月預算；分類排行與逐月趨勢。
- **備份**：一鍵備份、還原前預覽、還原後可復原、7 天提醒、CSV 匯出。
- **介面**：繁體中文／英文，淺色／深色，手機底部導覽、桌面上方導覽，可安裝成 App 並離線使用。

## 開發

需求：Node.js 20.19 以上。

```bash
npm install
npm run dev       # 開發伺服器
npm test          # Vitest（核心邏輯 + 畫面測試）
npm run lint
npm run build     # 型別檢查 + 正式建置
```

### 專案結構

```
src/
├── core/        記帳核心：資料模型、IndexedDB（Dexie）、驗證、報表、備份。不依賴 UI。
├── app/         App 外框：版面、資料庫 Provider
├── features/    功能頁面（transactions、accounts、overview、recurring、backup、settings、rates、onboarding）
├── ui/          共用元件與格式化工具
├── locales/     zh-TW／en-US 翻譯
└── test/        測試輔助（fake-indexeddb 測試資料庫、renderApp）
```

資料模型的設計（整數金額、由交易推算餘額、轉帳雙分錄、匯率換算）寫在 [`src/core/README.md`](src/core/README.md)。

## 部署

用 Vercel 等靜態網站主機即可：

- 建置指令：`npm run build`
- 輸出目錄：`dist`

`vercel.json` 會把所有路徑導回 `index.html`，讓 `/transactions` 這類網址重新整理時也能正常打開。App 是 PWA，部署新版後，使用者下次打開時會自動更新。

## 版本

版本號寫在 `package.json`，每個版本的變更記在 [`CHANGELOG.md`](CHANGELOG.md)。目前還在開發階段，版本號是 `0.x.y`：

- **有新功能或改動**：中間的數字加 1，最後一位歸零，例如 `0.2.0` → `0.3.0`。
- **只修 bug**：最後一位加 1，例如 `0.2.0` → `0.2.1`。
- 等功能穩定、準備正式推廣時，再改成 `1.0.0`。

發佈新版的步驟：

1. 更新 `package.json` 的版本號，並在 `CHANGELOG.md` 最上面加上這一版的變更，合併到 `main`。
2. 在 GitHub 的 **Releases → Draft a new release** 建立新版本：tag 填 `v0.3.0` 這種格式，Target 選 `main`，內容貼上 `CHANGELOG.md` 裡這一版的段落。

使用者的 App 會自動更新到最新部署的版本，所以 tag 主要是用來對照「線上跑的是哪一版」，有問題時也方便回到上一版重新部署。
